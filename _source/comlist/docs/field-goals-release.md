# 目標達成メニューとミッションボード

実装・検証のみ。本番・日次生成元・定期ジョブ・main・Pagesは未変更。公開承認後に反映する。

## 表示と集計

- 見込みは「紹介につながった人」。今月の初期目標3人、月別設定可能。紹介を実施し、成果を確認した人物IDを月内重複除外する。紹介件数から人数を推測しない。
- オリエン・初個別・新友達は人、紹介・個別は件。日報は活動月の最新累計だけを使い、日ごとの累計を合算しない。個別と初個別の包含関係も仮定しない。未報告・未設定は0と別表示。
- 5指標の不足と今週の必要数は、確認済み実績と目標から計算する。日本時間の月曜～日曜で、月末までの残り日数に対する今週の残り日数を使い均等配分して切り上げる。
- 打診中・確定・実施・延期・取消を区別。確定予定だけでは達成にしない。見込みの予定人数は「実施され、紹介につながったと確認できた場合」の条件付き表示。転換率による予測なし。
- 追加実施は日報の活動日より後だけ加算。日報更新後は対象日以前の追加分を加算保留とし、累計と二重計上しない。人数指標は本人が月内・日報との非重複を確認した記録だけ追加する。同日や日報外の実績を推測で足さない。
- 今日の行動は実在する人脈から本人が選び、目的と期限を入力する。既存の約束日・カテゴリ順で相談相手の候補を提案し、返信待ちを表示する。候補だけで予定・実績・連絡を実行しない。既存の人脈詳細から予定編集へつながる。

## ミッションボード

見込みの達成マス（初期3マス）、5指標の進捗ゲージ、今週のミッション、今日の一手、週スタンプ、月のお祝いを表示する。予定は薄い色、実施確認は濃い色に加え文字で区別する。ポイントによる実績加算・人物ランキング・欠席ペナルティはない。

本人が「今週ミッションを決める」で必要数を確認した後、開始日と目標を固定する。週スタンプは、開始時の実績を除いた日付付きの明示的な実施記録だけで判定する。日報累計の増加だけでは週達成を作らない。未報告・未設定の項目は対象外と明記する。月またぎの週は活動月別に分ける。過去のミッション・取消記録は削除しない。記録訂正で達成条件を満たさなくなった場合は達成表示を外し、履歴は残す。

お祝いは同期済みの確認記録にだけ連動する。端末の暗号化キャッシュに月・週の演出済み印を保存し、同じ端末での再読込・同期・取消後の再達成で再発火しない。端末が違えば初回表示になる可能性はある。キャッシュ保存に失敗した場合は演出しない。OSのprefers-reduced-motionと画面の「動きを減らす」に対応し、進捗バー・ボタン・ダイアログをキーボードとスクリーンリーダーで操作できる。

所有者が承認後に `setupFieldGoalsSheet()` を明示実行する。シートがなければ作成、既存用途があれば中止、正しい設定とデータがあれば保持する。API要求で自動作成しない。

| 列 | 見出し | 内容 |
| --- | --- | --- |
| A | 状態JSON | 月別目標・人物ID・行動記録・週ミッション |
| B | 更新番号 | 保存ごとの単調増加整数 |
| C | 最終リクエストID | 応答消失後の同一要求の重複防止 |
| D | 最終要求SHA256 | 同じIDで異なる内容を送ることの拒否 |

状態1件をA2以降に2万文字ずつ分割して保存し、B2:D2に更新番号と要求情報を保持する。短縮更新時は余った専用範囲を空にし、記録そのものは削除しない。読取・保存はロック内で一括処理し、B3:D以降に別のデータがあれば拒否する。JSON内の項目：

- `goals[YYYY-MM]`: 見込み人数目標 `prospects` と5指標目標 `metrics`。
- `persons`: UUID `id`、人脈の `name` と行位置ヒント `row`。初めて本人が選んで保存した際にUUIDを発行する。
- `records`: UUID `id`、`personId`、活動種別 `kind`、状態 `status`、予定／実施日 `date`、行動期限 `dueDate`、目的 `purpose`、紹介成果確認 `outcomeConfirmed`、人数の非重複確認 `newPersonForMonth`。
- `missions`: 週・月のキー `id`、`month`、月曜 `weekStart`、開始日 `startDate`、固定必要数 `targets`、開始前の記録・人物ID `baseline`。

新しい人物は一意な実在の人脈だけに対応させる。行移動は一意な名前で解決する。名前変更・同名で不明な場合は別IDを推測で発行せず管理者確認とする。既存人物IDの付替え、記録の削除、確定済み週ミッションの削除・書換えを拒否する。取消で記録を残す。

個人情報は非公開シートと既存PBKDF2/AES-GCMキャッシュのみ。公開JSON・平文localStorageには出さない。演出済み印・動きを減らす設定は暗号化した端末キャッシュだけに保存し、GASへは保存しない。

APIは既存トークンの `fieldGoalsRead`／`fieldGoalsWrite`。ScriptLock・内容ハッシュ・更新番号で同時編集を検出し、未同期入力を保持して拒否する。最後のrequestIdと同じ内容の再試行を重複保存しない。再読込で勝手に送信せず、本人が再試行・取消を選ぶ。「保存中／同期済み／この端末のみ／同期失敗」を区別する。

合言葉のない端末でも未送信の下書きを続けて編集できる。一度送信を試みた要求は内容を固定して再試行する。明示した再試行ボタンから既存の合言葉入力へ進める。保存記録をまだ取得していない段階は「未取得／未計算」とし、0人達成と見なさない。

新API_TOKEN・トリガー・OAuthスコープ・公開範囲変更は不要。既存GAS実行者には新規シートの編集権限が必要。今回、権限やセキュリティ設定は変更していない。

上限は200人物・300行動・120目標月・120週ミッション、JSON100万文字。分割によりシート1セルの上限に依存しない。超過時は記録を削除せず保存を拒否する。長期運用では保管方式の拡張が必要になる可能性がある。
