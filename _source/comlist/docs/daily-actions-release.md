# マイベストライフ：行動と保存・同期の改善

## 今回の範囲

実装1〜4をローカルの独立した取得先で変更した。既存のユーザー作業ディレクトリ、本番スプレッドシート、GASデプロイ、GitHub上のブランチには変更していない。push・マージ・公開は未実施。

- 分析：A/Bの「次会う日なし」はKPIと一覧で同じ集合を使う。超過連絡候補では判断したアクション日をラベル付きで表示する。会う準備では次会う日を表示する。
- タスク：端末反映、端末への保存失敗、保存中、同期済み、未同期、同期失敗と再試行を表示する。既存pendingキューを保持し、1タスクの書き込みを直列化する。送信前の反復操作は最新の状態にまとめ、同じ操作の重複送信を抑止する。再取得中の操作と古い応答による巻戻りも防ぐ。
- 人脈編集：読み取り・登録・更新結果に `_version` を追加し、編集・プロフィール・一括更新・連絡記録はロック内で比較してから保存する。内容のバージョンはA:Zの値を正規化した完全一致の文字列で、計算される現在の年齢を除く。AD:AF設定後は記録状態も含む。行移動は一意な名前で解決する。競合は書かず、入力とエラーを保持する。保存中に画面を切り替えても古い再取得が対象オブジェクトを置き換えない。
- ホーム：今日中の期限→今日の重要3件→今日の予定→連絡する人。重要3件は未完了から選び、実タスクへ移動するための参照を表示する。チェックボックスの重複は作らない。昨日からの戦果は件数の要約と折り畳んだ詳細にする。期限切れ・他タスクへのアクセス、HP計算を維持する。
- ガーデン：今日連絡する最大3人を提案する。期限のある約束を先に、期限の古い順、同じ日ならA→B→C→D、日未設定はカテゴリ周期を理由に表示する。将来の約束は前倒ししない。当日記録済みの人は候補から外す。候補と個別カードから「連絡した／返信待ち／次の予定を決める」を確認して記録できる。操作しなければ記録も通信も行わない。
- 「連絡した」だけ履歴へ年付き日付を追記し、期限が過ぎた／未設定のアクション日を既存カテゴリ周期の次回日へ進める。将来のアクション日、会う予定、プロフィールは保持する。「返信待ち」は記録状態だけを保存する。「次の予定を決める」は状態を記録した後に既存予定エディタを開く。日付を自動で決めない。
- 連絡記録の未確認操作は既存の暗号化キャッシュに保持する。同じrequestIdで明示的に再試行する。サーバー側のAD:AFに最後の操作の受領情報を保存し、応答消失後の再試行でも再度履歴を追記しない。別の操作後に古い操作を送ればバージョン競合で止める。編集フォームが開いている間は再試行を止め、入力を守る。

## 公開前に必要なGAS作業

1. 現在の本番GASを取得してこのリポジトリの `sheet-api.gs` との差分を確認する。既存独自変更を保持し、テスト用スプレッドシートと別デプロイで確認する。本番のコードを一方的に差し替えない。
2. 本番AA:ACには既存の招待文があるため、上書き・移動しない。新規記録はAD:AFを使用する。AD:AFに既存の値・数式・見出し・用途がないか確認する。所有者が `setupContactTrackingSheet()` を実行する。列数が足りなければAD:AFを追加し、空の列だけに「連絡記録状態／連絡記録日／連絡記録リクエスト」を設定する。既存データがあれば処理は中止する。A:ACの既存列は移動しない。所有者以外からシステム列AFを編集させない運用にする。
3. この追加機能に新しいAPI_TOKENや追加トリガーは不要。既存のGAS実行者にスプレッドシートを編集する権限と、AD:AFが保護されている場合はその編集権限が必要。外部サービスへの新しいOAuthスコープは追加しない。
4. 承認後にGASの既存ウェブアプリのデプロイを更新し、読み取りが `_version` を返し、競合した書き込みが変更なしで失敗することを確認する。URLを変える場合は `API_URL` を見直す。
5. GASを先に更新する。新コードはversionなしの人脈更新を拒否するので、旧画面を開いたままの端末は編集できなくなる。利用者に新画面と最新データの再取得を案内する。新画面で旧GASを使うと `_version` を取得できず編集を止める。連絡記録列未設定の状態では連絡記録は保存しない。
