# 画面の機能と公開の仕組み

CLAUDE.md / AGENTS.md から移した機能の説明。日次の流れと禁止事項は CLAUDE.md に残している。

## 分析タブ（2026-09-27）

人脈のカテゴリ別人数・連絡予定の超過・A/Bの予定未設定、担当者別の期限切れ、今週の連絡と面会準備を表示する。カテゴリと担当者別は棒グラフ、期限切れ推移は折れ線グラフ。対象者からカード、タスクから今日のタスクへ移動できる。

`analysis_history.js` が日次ビルドで `dailyTasks.analysisLog` に日別の件数だけを56日分保存する（同日は上書き、暗号化対象）。7日前の記録がない場合は記録待ちと表示する。画面だけの `--reuse-data` では記録を追加しない。完了チェックは取得元の期限切れ件数に反映しない。

## カレンダーとイベント

「カレンダー・イベント」メニューで空き候補・Googleカレンダーと今後のイベントを同時に表示する。PCではカレンダーを左、イベントを右に並べ、画面幅1100px以下では縦に並べる。旧 `setView('events')` はカレンダー画面へ移動する。イベント追加・編集・最新取得は同じ画面で使える。

## 人物像（AB列）

人脈リストのAB列は、見出しが「人物像」の場合だけ読み取り専用で取り込む。人物詳細の「仲間づくりのヒント」の上に表示し、空欄は省略する。HTMLは実行せず、改行を保って表示する。編集対象の26列と更新番号の計算には加えない。端末の保存データに古い人物像がある場合は、公開データの人物像を優先する。AB列を空欄に戻した場合も反映する。

取得には更新した `sheet-api.gs` の反映が必要。日次スナップショットにも人物像を含め、公開時は連絡先と同じ暗号化データに入れる。

人脈ガーデンの友達ボタンにマウスを置くと、「出会い(どこで)」、AB列の人物像、「現在の年齢」をポップアップで表示する。空欄は「未記入」と表示し、改行を保つ。キーボードでボタンを選んだときにも表示し、Escapeで閉じられる。スマホは550ミリ秒の長押しで開き、指を離しても表示を保つ。「×」か外側のタップで閉じる。通常のタップは詳細を開き、スクロールや中断時は長押しを取り消す。

## 本日期限のタスクバッジ

- 「今日中の期限タスク」は本人担当だけを表示する。担当は `owner` を優先し、なければ既存の詳細欄の担当者判定を使う。「りゅうちゃん」「自分」、本人を含む共同担当、担当表示のない本人タスクを対象にする。次にやること・優先タスク・バッジも同じ条件で絞り込む。
- 自分の本日期限タスクが未完了なら、各タスクと「今日中の期限タスク」の見出し、「今日のタスク」メニューに赤く点滅するバッジを表示する。見出し・メニューは未完了件数を表示する。
- `section: today` かつ `due` が日本時間の今日で、データの日付も今日のものだけが対象。担当は「りゅうちゃん」「自分」、または担当のない本人タスク。他の担当者は除く。
- 完了・完了解除・端末間同期で更新し、日付が変わった場合は古いデータのバッジを消す。動きを減らす端末設定では点滅しない。

## 分割公開と端末キャッシュ（2026-09-30）

- `build.js` は `artifact_bundle.js` でハッシュ付きのCSS・JS・画像・暗号化データを生成する。`comlist.html` のmanifest参照が同じ世代の全依存を示す。画像は元のバイト列を維持する。
- `tools/publish_bundle.js` が公開依存と安全なソース一覧をコピーし、`_source/comlist/` にソース・テストを保存する。認証情報・`_work`・格言履歴はコピーしない。
- 人物・イベントの正本はGoogle Sheets。API保存成功後に暗号化キャッシュへ保存し、同じ日次データのリロードで復元する。個人情報の平文をlocalStorageへ保存しない。
- 完了チェックの未送信操作はtrue/falseを保持する。解除の送信失敗でも古いチェックを復活させない。
- 日次公開には `tools/deploy_garden.ps1` と同じ版の外部 `_deploy_garden.ps1` を使う。
- テスト：`npm test`、実ブラウザ：`npm run test:browser`（架空データとローカルAPIのみ）。

## 現場数（2026-10-03）

- 「現場数」タブは Notion「日別数値進捗」の月累計を表示する。データソースは `collection://a94914fb-30c5-462f-b7a5-88c1d8e16ff0`、月別の選定基準は <https://app.notion.com/p/3ed4057e22428164b6acca0ac58c1045>。
- 各活動月につき「原文目標月」が活動月と一致し、数値が記録されている行のうち、活動日が最新の1行を選ぶ。同一活動日は報告日が新しいものを選ぶ。翌月初日の報告でも活動月に含める。日別の月累計は加算しない。空欄を0として扱わない。
- 毎日の日次更新では、5項目（オリエン、紹介、個別、初個別、新友達）の月累計・月目標、活動日、報告日、元ページURLを全月分まとめて `_work/field_progress.json` に保存してから `garden_publish.ps1` を実行する。JSONの形は `field_progress.js` と `test/field_progress.test.js` を参照。月末の記録がない月には `partial: true` を付ける。
- `build.js` はこのファイルがあれば検証して暗号化データに含め、なければ前回の暗号化データを引き継ぐ。画面だけを直す `--reuse-data` では前回値を維持する。日次更新でNotion取得に失敗した場合は公開を止める。推測値を書かない。`_work` の平文ファイルは従来どおり公開後に削除する。
- 日別カレンダーの「実」は同じデータの `days` 配列から表示する。各行は `activityDate`、`reportDate`、`url`、`values`（5項目）を持ち、Notionの「進捗」欄を活動日に対応させる。月累計を差分で日別に推測しない。空欄は `null`、明示された0は0。同じ活動日は最新の報告を採用する。日報の実績とアプリの完了記録は加算しない。「予」は既存の確定予定から表示する。
- 日次取得では月別の `months` と日別の `days`、実際の取得完了日時 `checkedAt` を保存する。SQLの利用上限・結果の件数制限時は `view://70b16970-4d03-4d29-b409-6f4b1f243f58` を100行ずつ、`has_more` が false になるまで取得する。全行を `_work/field_progress_rows.json` に `{complete:true,rows:[...]}` として保存し、`compose_field_progress.js --input ... --checked-at <UTC ISO日時> --out _work/field_progress.json` で変換する。原文目標月は `YYYY-MM` と `◎YYYY年M月度実績` に対応する。`garden_publish.ps1` は `--verify` で確認日が日本時間の当日か検査し、欠落・古い確認日時・日別配列なしを段 `field-progress` で停止する。新しい活動記録がない日は活動日・報告日を変更せず、画面の「Notion確認」の日時だけ更新する。
- 月・週カレンダーの各週の右端に5項目の実績・予定の週合計を表示する。月をまたぐ週は選択中の月の日付だけを集計し、前月・翌月分を除く。週合計の日付範囲と記録日数も対象月内に絞る。実績は記録済みの日別進捗を加算し、未記録日は0とみなさない。一部記録の合計には「※」を付け、全日未記録なら「—」。人数も日別の数値を加算した延べ人数。予定は日別に表示する確定予定の合計。スマホでは各週の7日分の後に週合計を表示する。

## カレンダーの空き候補

- カレンダーメニューの90分空き候補は `_assets/js/calendar-slots.js` の週間カレンダーで表示する。月曜始まり、縦軸は時間、対象期間が翌週にまたがる場合は週を切り替える。スマホはカレンダー内を横スクロール。空き時間の判定と予定入力のみを開く動作は従来どおり。


### 会う予定のリマインドの端末間同期

書き込み合言葉を設定した端末では、リマインドの完了状態を Apps Script の reminderState API と共有する。開いたとき・画面に戻ったとき・60秒ごと・完了操作時に同期する。「リマインドを同期」から手動でも確認できる。未送信の完了記録は暗号化キャッシュに残し、同期成功までバッジを残す。以前この端末で完了した記録も初回同期で送る。

送信する識別子は従来のリマインド ID を SHA-256 にした64桁で、名前や予定日は送らない。GAS は REMINDER_DONE_ のバケットに完了のみを保存し、日次タスクの14日保存期限とは独立して保持する。完了は取り消さず、別端末の古い状態で未完了に戻さない。同期先の合言葉は既存の API_TOKEN を使う。

GAS の既存コードを維持して反映する場合は、sheet-api.gs 末尾の Completion-only reminder state 以降を ReminderSync.gs として1回だけ追加し、既存ウェブアプリのデプロイを新しいバージョンへ更新する。sheet-api.gs 全体へ差し替える場合は別の ReminderSync.gs を重ねて置かない（doPost のラッパーが重複するため）。


### 祝日の空き候補

内閣府の公式CSV（https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv）の祝日・振替休日・国民の休日は、端末の weekend 設定で計算する。設定画面の表示は「土日・祝日」。既存の土日設定を維持し、カレンダー見出しに祝日名を表示する。予定・移動余裕・除外日は従来どおり優先する。build.js の旧空き候補も同じ公式祝日判定を使う。

収録データは1955〜2027年。公式の翌年分は毎年2月に公表されるので、その後に `node tools/update_japan_holidays.js` を実行して再ビルド・公開する。更新スクリプトは日付・件数を検査し、不完全なデータや以前の年までしかないデータへの置き換えを止める。ブラウザは外部の祝日カレンダーや通信を必要としない。
