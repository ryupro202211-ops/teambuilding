# 現場数カレンダーと90分空き候補（公開前）

実装対象は、現場数の月／週カレンダーと、カレンダーメニュー先頭の空き候補。予定詳細・AA「仲間づくりアドバイス」の既存変更を保持した。保存済みの人脈、行動、成果、週ミッションのIDと履歴は変更しない。Google予定を5指標へ自動分類しない。

## 集計

- 月／週、前後、今日へ移動。週は月曜始まり、日本時間。月をまたぐ週も7日表示する。
- 日別は保存済み行動記録の実施／確定予定だけ。日報の月累計から日別実績を作らない。行動データ未取得は `?`。
- オリエン・初個別・新友達は人数（人物IDで重複除外）、紹介・個別は件数。紹介につながった人3人は既存の成果カードで月内ユニーク集計し、5指標へ混ぜない。
- 月目標T、日報＋重複確認済み追加実績A、不足max(0,T−A)、将来の確定予定P、予定後不足max(0,T−A−P)、残り日数Dと平均ペースを表示する。
- Pは日報対象日以後の記録。人数指標は「月内の新しい人」の確認が必要。実施済み人物との重複を除外する。打診・取消・延期・期限超過・実施済みはPに含めない。
- 未設定目標と0を区別する。過去月は期間終了、未来月は全日数、今月は今日を含む。0日で割らない。

## 空き候補

- 現在時刻から正確に7日後まで。90分以上の空きを90分ずつ区切り、入る枠をすべて選び、月曜始まりの週間カレンダー上へ表示する。対象期間が翌週にまたがる場合は前後の週へ移動できる。スマホではカレンダー部分を横にスクロールする。
- メインカレンダーのみを取得。取得日時・範囲・完全性を表示。別カレンダーを含むとは表示しない。
- 終日・日またぎ・重複予定を統合し、前後の移動余裕を差し引く。取消・辞退・transparentはbusy対象外。情報不明・部分取得・3時間超の古い取得・取得失敗・範囲不足では候補を出さない。
- 活動時間は旧表示の平日12:00〜13:30／18:00〜24:00、土日8:00〜24:00を初期入力。移動余裕は未設定。利用者が時間帯・余裕・除外日（休み／祝日等）を確認し端末へ保存するまで候補を表示しない。
- 設定と取得結果は既存の暗号化キャッシュへ保存。設定はこの端末のみ。再取得に失敗した結果は再読込でも候補を復活させない。
- ボタンは既存の予定入力画面に日付・開始・終了を入力するだけ。保存・招待・連絡は送らない。入力中の予定を別候補で上書きしない。キャンセル後は新しい要求IDになる。

## 本番反映（未実施）

1. 最新のmainとGAS本番を取得し、現在の変更と差分を確認する。GASはリポジトリ一致を前提にせず、既存のAA表示、連絡記録、目標・イベントのCAS／冪等性を保持する。
2. 承認後に、同じGASプロジェクト／URLのソースと既存デプロイを更新する。新しい認証スコープ、Advanced Calendarサービス、トークン、シート列は不要。既存CalendarAppの読取権限を使う。
3. 24:00で終了する予定を保存する場合だけ、管理者が `enableMidnightEventEndValidation()` を一度実行する。イベント管理シートのE列入力規則だけを拡張し、セル値・他の列・保護は変更しない。未実行でも通常時刻の登録は従来どおり。24:00の保存は規則確認で止める。
4. 素材スナップショットを更新・再取得し、calendarInfoと認証済み `read / calendarAvailability` を確認する。旧V2スナップショットも互換読み込みし、確認できない空きを推測しない。
5. 公開承認後に日次生成元へソース・テスト・UIを再適用する。対象：`_assets/`、build.js、event_records.js、material_snapshot.js、fetch_materials.js、sheet-api.gs、tools、test。新しいJS3ファイルも含める。未公開のまま稼働中の自動生成元へ適用すると翌朝に自動公開され得るため、現時点では適用していない。
6. 日次生成元でテストと通常ビルドを実行し、暗号化された予定／AA素材を含む生成物を作る。レビュー後にpush／main反映／Pages確認を行う。現在のローカルUI再ビルドは既存暗号化データをそのまま保持しており、新しい実素材を取得していない。

## 検証と残課題

`node --test test/*.test.js`、ESLint、`node tools/test_browser.cjs`、bundle verify、git diff --checkを実行する。ブラウザはPC1280pxとスマホ390px、合成データ・ローカルAPIのみ。実データへの書き込み・本番送信は行わない。

境界：31日月の4日目はD28、T10/A4/P3で不足6・予定後3。月跨ぎ、うるう年、日本時間の境界、89分除外／90分採用、7日後の終端、終日・重複・辞退、取得失敗と再読込、部分・古い取得、反復クリック、未保存入力とキャンセルを確認する。

GAS本番への反映、実カレンダーでの結合確認、日次生成元への再適用は未実施。実データでの動作は公開承認後の確認事項。ビジョン画像はユーザーのローカル保存先が未提示で、既知のDownloadsファイル名にも見つからず保留。画像欄の準備だけを保持し、別画像で代用しない。
